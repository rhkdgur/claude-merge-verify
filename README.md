# merge-verify

Claude Code 스킬 — git merge 충돌을 수동으로 해결한 뒤, 커밋하기 전 그 해결 결과가
올바른지 3-way diff로 검증한다.

## 왜 필요한가

머지 충돌을 해결하다 보면 다음과 같은 실수가 쉽게 발생한다.

- 한쪽 브랜치에서만 추가/수정한 로직이 해결 결과에서 빠짐
- 같은 로직(메서드, import, 필드, 설정)이 중복으로 들어감
- 양쪽 변경을 기계적으로 합쳤지만 의미가 어긋남 (컴파일은 되지만 기능이 깨지는 회귀)

이런 문제는 `git status`나 `git diff`만으로는 찾기 어렵다. 이미 `git add`까지 끝낸
상태라면 어떤 파일이 실제로 충돌이 났었는지조차 알기 힘들다. 이 스킬은
`git merge-tree`로 3-way 병합을 다시 계산해 실제 충돌 파일만 정확히 추려내고,
base/ours/theirs 세 지점을 비교해 위 문제를 찾아낸다.

## 사용 조건

- 머지 커밋을 만들기 전(`MERGE_HEAD`가 존재하는 상태)에만 동작한다.
- 이미 사용자가 충돌 해결을 진행 중인 상태를 검증하는 용도다. 새로 머지를
  시작하거나 충돌을 대신 해결해주는 스킬이 아니다.
- 읽기 전용으로만 동작한다 — 파일 수정이나 커밋은 수행하지 않고, 문제가
  발견되면 무엇이 문제인지와 어떻게 고쳐야 하는지만 보고한다.

## 동작 방식

1. `MERGE_HEAD` 존재 여부로 적용 가능한 상태인지 확인
2. `HEAD`(ours) / `MERGE_HEAD`(theirs) / `git merge-base`(base) 세 지점 확보
3. `git merge-tree`로 실제 충돌이 났던 파일만 정확히 추출 (자동 병합된 파일은 검증 대상에서 제외)
4. 대상 파일별로 base→ours, base→theirs 변경 내용과 실제 해결 결과(staged 또는 워킹트리)를
   비교해 누락·중복·논리적 충돌 여부를 확인
5. 충돌 마커(`<<<<<<<`, `=======`, `>>>>>>>`) 잔존 여부 재검사
6. 파일별 검증 결과 보고 — 문제없으면 커밋 진행 안내, 회귀가 있으면 우선순위 높음으로 표시

대상 파일이 많을 경우(대략 5개 이상) 서브에이전트에 위임해 메인 컨텍스트를 아낀다.

## 한계

- 코드를 읽고 import/타입/시그니처를 대조하는 방식으로 "컴파일될 것 같다"를
  판단하는 것이지, 실제 빌드를 돌려 검증하지는 않는다. 빌드 도구가 있다면
  별도로 컴파일을 한 번 돌려보는 걸 권장한다.
- 이미 머지 커밋이 끝난 상태나, 원격과의 divergence·push 가능 여부 체크는
  범위 밖이다.

## 설치

`.claude/skills/merge-verify/` 디렉터리를 프로젝트에 복사하면 `/merge-verify`
슬래시 커맨드로 바로 사용할 수 있다.
